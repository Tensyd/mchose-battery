# 兼容性与适配状态

本文件区分「已验证支持」「离线候选」「未评估」三件事。**只有本机实测通过的组合才算支持**；代码里存在一套协议实现，不等于任何同系列设备都能读。

## 一、当前支持

| 设备 | 接口（VID:PID / Usage Page:Usage） | 协议 | 2.4G 实测 |
| --- | --- | --- | --- |
| A7 V2 Ultra+ | `3837:100B` / `FF01:0x0001` | 81 字节 Feature Report，反码载荷 | 是 |
| G87 V2 | `3837:201B` / `FF02:0x0002` | 20 字节 Output Report，累加校验 | 是 |
| V9 PRO | `291D:385D` / `FF90:0x0001` | 64 字节 Output Report，固定签名 | 是 |

已核对的硬件信息仍不完整：接收器固件、鼠标/键盘固件版本、Windows 版本组合尚未逐项记录。上表只声明「这些设备在这台机器上读出过正确电量」，不外推到同型号的其他固件批次。

### 状态显示规则

| 状态 | 条件 | 展示 |
| --- | --- | --- |
| 实时值 | 本次刷新读到有效电量 | 百分比与进度条，≤20% 标红 |
| 上次读数 | 设备接受查询但无响应（休眠常见），且是同一个接口 | 百分比转灰，不显示文字 |
| 不可用 | 接收器缺失、接口打不开、读取失败、换成了别的接口 | `--` |

鼠标与键盘保留上次读数，耳机不保留：接收器无法区分「耳机已关闭」和「超出范围」，沿用旧值等于编造。

## 二、证据等级

新增设备按证据推进，等级不够就停在原处：

| 等级 | 需要什么 | 允许做什么 |
| --- | --- | --- |
| E0 线索 | 商品名、外观相似、零散 PID | 只记录，不发送任何查询 |
| E1 身份 | 实机枚举出的接口、版本信息 | 列入候选 |
| E2 协议 | 可追溯的官方资料、官方软件电量事务抓包，或来源明确可核对的实现 | 设计离线适配 |
| E3 离线通过 | 真实来源报文回放、边界与模拟事务测试 | 标记「待实机验证」，默认不查询 |
| E4 实机通过 | 在本程序中按验收矩阵跑通 | 才写进支持表 |

E3 与 E4 之间没有捷径：别人的程序能读，不能替代本项目在目标硬件上的验证。

## 五、已知的解析器待确认行为

两处保持现状，因为收紧校验需要实测依据，不能凭推断修改：

1. **G87 七字节响应免校验**：长度 7 时跳过末字节校验。真实短帧是否可信未确认。
2. **V9 载荷无请求/响应区分**：当前只校验两字节签名与电量范围，因此请求帧本身也会被解析成 1%。真实设备是否回显请求未确认。

两项都有对应的特征测试固定当前行为（`g87_parser_accepts_seven_byte_frame_without_checksum`、`v9_parser_treats_request_echo_as_level`）。若日后取得证据收紧，测试会先失败，避免悄悄改变现有设备的表现。

## 六、提交新设备信息

有设备的话，提供以下内容即可推进到 E2／E3；缺项就写「未知」，不要猜：

- 完整型号、硬件/固件版本、接收器版本、连接方式（2.4G／有线／蓝牙）。
- Windows 版本、官方软件版本。
- HID 接口：VID/PID、Usage Page/Usage、Report ID、报告长度。
- 报文：请求与响应的完整字节、方向、实际长度、先后顺序。
- 对照：同一时刻官方软件显示的电量，以及设备处于休眠／充电／关闭时的表现。

序列号与设备路径请脱敏，不要附带键盘输入或音频数据。

### 先用 `--diagnose` 收集接口清单

程序带一个被动枚举模式，只读取系统 HID 接口列表，**不打开设备、不发送任何指令**：

```powershell
MCHOSE-Battery.exe --diagnose
```

报告写在 exe 同目录的 `mchose-diagnose.txt`（目录不可写时改存临时目录），包含三部分：

1. 厂商自定义接口（Usage Page ≥ `FF00`）——新型号最可能藏在这里；
2. 已知厂商 ID 的其他接口——用来发现同一接收器上的附加集合；
3. 三款已支持型号是否被当前机器识别。

报告不读取序列号与设备路径，因为它们可能被贴到公开 issue 里。拿到报告后仍需补充上面的固件版本、报文与电量对照，才能进入 E2。
